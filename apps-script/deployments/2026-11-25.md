# Journal setup-export compatibility deployment

On 25 November 2026 the production SQLite check confirmed 192 trades, 394 events, a verified backup, four pending export records and `SHEETS_REJECTED_REQUEST`. Account reads and both deployed isolated Core/Scalp exit/replay checks passed. No broker orders were sent and production positions/services remained unchanged.

The bound Google Apps Script project `1jJdFDM2TWvJ_s7aWls_lTxQBw1bVAFrZcMsQ4Lbpho4j-K4If0mPie4m` still used an older trade-only implementation and active web-app Version 2 (11 September). Its source had neither the `setup_decision` route nor a `SetupDecisions` sheet handler. This is incompatible with the SQLite export queue, which emits `setup_decision` for saved setups.

A narrow compatibility addition was saved and deployed as Version 3 at 09:09 IST. It adds authenticated setup-decision handling, the canonical setup columns, script locking and an upsert keyed by setup ID. It creates the setup tab on the first valid saved export. The existing trade-writing code was preserved byte-for-byte apart from adding the new action branch; existing trade and journey rows, script properties, credentials, deployment URL, execution identity and access settings were not changed. The canonical repository implementation already contains the complete setup handler; this deployment deliberately preserved the older trade-only implementation instead of upgrading unrelated trade columns at the same time.

The UI confirmed the deployment update. A new signed AWS export and end-to-end duplicate replay run is still required before claiming the previously queued records were exported. Existing saved records must be retried; do not insert fabricated trades into the production journal.

`tests/apps-script-setup-export.test.mjs` exercises the canonical handler using an isolated spreadsheet implementation: setup ID replay leaves one row, saved trade/journey data remain untouched, invalid credentials and incomplete records cannot create setup rows, and zero/false updates are preserved. The test never accesses a real Google Sheet.

This change does not enable real-money trading or verify actual broker orders/stops or WebSocket exits. PR28 and PR30 remain unmerged.
